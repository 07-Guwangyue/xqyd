## 3. 数据文件说明

路径：项目根目录的 `src/data.txt`。编码：UTF-8，不带 BOM。分隔方式：空白字符；以 `#` 开头的行是说明，不是数据。小区名称、户号中不能包含空格。

```text
1 甲区 H01 2024 1 65 28
```

| 列 | 字段 | 示例含义 |
| --- | --- | --- |
| 1 | 小区编号，正整数 | 1 |
| 2 | 小区名称 | 甲区 |
| 3 | 户号，区分大小写 | H01；甲区 H01 与乙区 H01 是两户 |
| 4 | 年份 | 2024 |
| 5 | 月份 | 1，即一月 |
| 6 | 峰时电量，kWh | 65 |
| 7 | 谷时电量，kWh | 28 |

题目表格里的 `2024-07` 在文件中拆成 `2024 7` 两列，含义相同，便于读取。电费不存入文件，由程序按照电量计算。

两区各 25 户，每户 2024 年 1—12 月、2025 年 1—12 月各一条，没有缺月或重复月份。正常加载应显示“1200 条记录，2 个小区，50 户”。文件按小区、住户、年、月排列，统计逻辑也允许记录乱序。

关键核对数据：7 月严格对应题目两个示例；8 月两区户均峰时增量同为 30，用来检查并列时的编号排序；9 月甲区增量 -5、乙区增量 0，用来检查非正增长。其余月份采用简单规律形成模拟读数，不代表真实住户情况。

## 4. 计算过程与阅读顺序

可以先手算一户一个月，再理解整个程序：峰时 120、谷时 20，则总电量是 `120 + 20 = 140 kWh`，电费是 `120 × 0.60 + 20 × 0.30 = 78 元`。

小区月报按相同小区、相同年月累计。25 户都使用上述读数时，峰时合计 3000，总电量 3500，总电费 1950；再除以 25 得户均电量 140、户均电费 78。推荐采用的户均峰时电量则是 `3000 / 25 = 120`，不要用 140 替代它。

推荐差值计算：`第二年该月峰时合计 / 第二年该月户数 - 第一年该月峰时合计 / 第一年该月户数`。程序分别汇总两年，而不是直接相减峰时总量。

建议依次阅读：

1. `Record`：理解一条原始记录。
2. `main` 与两个菜单：理解从哪里进入功能。
3. `queryAnnualBill`：学习按多个条件查找并累计。
4. `AreaSummary` 与 `summarizeMonth`：学习从逐户记录得到小区汇总。
5. `sortValue` 与 `sortSummaries`：理解选择排序和并列规则。
6. `recommendAreas`：把筛选、两年比较、排序连起来。
7. 输入、文件读取、完整性检查：最后理解程序如何拦截异常输入。

源代码已经按模块、主要变量、循环及关键判断写明作用。学习时建议自己画一遍数据流，并在调试器中观察一次累加过程。

## 5. 初稿不足和后续修改方向

这里的不足是后续改进清单，不是故意留错计算结果。

| 当前不足 | 影响 | 后续可怎么改 |
| --- | --- | --- |
| 所有功能在一个 `.c` 文件中，数据使用全局变量 | 入门时方便阅读，代码增长后维护困难 | 熟悉后再拆成输入、数据、统计、菜单几个源文件；暂不急于拆分 |
| 记录上限 10000、小区上限 100，读取和查重多次顺序扫描 | 小样本够用，大文件速度慢、容量受限 | 先理解当前循环，再考虑动态数组或按复合键建立索引 |
| 文件错误只报告第一个问题然后退出 | 修复多处错误要反复运行 | 累计错误行号，最后统一显示；仍应拒绝用残缺文件统计 |
| 文件解析使用 `sscanf`，只适合受控模拟文件；未完整防护超长行、超范围整数字段、BOM | 任意外部文件的兼容性与健壮性不足 | 以后改为逐字段转换并检查范围、行长和编码；不要据此声称支持任意文件 |
| 过长的终端输入统一提示重输，户号不自动去首尾空格 | 用户复制户号时可能查不到 | 独立编写去除首尾空白的辅助函数 |
| 金额使用 `double`，门槛比较带 10⁻⁷ 元容差 | 存在浮点误差；未定义读数很多位小数时的正式计费舍入规则 | 后续明确电量精度、按月或按年舍入规则，考虑统一整数单位；不要只把结果显示两位当作内部精确计算 |
| 角色只通过数字选择，没有身份验证 | 适合本题演示，不具备真实权限保护 | 题目未要求登录，后续是否添加由实际需要决定 |
| 只读数据，改数据后需重新启动；没有编辑、导出功能 | 使用便利性有限 | 基本算法稳定后再考虑，避免初稿过度复杂 |
| 输出为普通文本，中文列宽未精确对齐；无图形界面 | 不同终端的观感可能有差异 | 可先增加分隔线、解释性文字及字符图 |
| 强制每户两年各 12 个月 | 满足题目完整数据前提，不能直接用于真实迁入迁出场景 | 如以后支持户数变化，需另行设计数据完整性规则；当前不扩展 |
| 只有两个小区的正式样本，部分排序指标顺序相同 | 常规演示不能充分证明所有排序分支 | 修改临时副本，让三种指标出现不同次序，再核对；已有一次临时样本验证，见测试文档 |
| 尚未配置 F5 调试、打包安装、跨平台自动检测 | 换机器仍需准备编译器 | 先用运行任务演示，之后再根据实际系统配置调试器 |

## 6. 留给你独立完成的三个小亮点

这三个位置只留了注释，没有填写实现。它们基于本题的计算结果展示，不是题目选做的数据生成工具。每次只做一个，改完立刻编译核对，保持基本功能输出正确。

### 留白 A：月报增加“峰时占比”（容易）

代码位置：`showMonthlyReport` 中的“留白 A”。

目标：解释“这个小区当月电量中，有多大比例集中在峰时”。提示：现成变量是 `s->peak` 和 `s->total`；结果显示为百分比。先想好总电量为 0 时如何避免除零，再调整表头和输出。注意 `printf` 输出百分号需要 `%%`。

独立核对：2025 年 7 月，甲区应为 85.71%，乙区应为 86.21%。这能帮助观察用电结构，但不要用它替换题目要求的推荐排序指标。

### 留白 B：推荐后增加一句原因解释（容易）

代码位置：`recommendAreas` 输出循环中的“留白 B”。

目标：在数字后面增加人能读懂的解释。先自己写出三个分支：增量大于 0、等于 0、小于 0，各输出一句说明，例如“户均峰时用电上升”“与上年持平”“较上年下降”。可以在有结果时统一注明“这是增长指标排序，尚未评估设备实际容量”。

现成变量是 `candidates[i].growth`。测试时分别使用 7 月和 9 月。负增长也要正常显示，不能因为解释文字而改变题目的筛选规则。

### 留白 C：用字符条形图显示增量（稍有挑战）

代码位置：`recommendAreas` 输出循环中的“留白 C”。

目标：自己编写一个接收增量参数的函数，用 `#` 数量表示增量。例如约定每个 `#` 表示 5 kWh，增量 40 时输出 8 个 `#`，25 时输出 5 个。思考是否取整、如何说明刻度、如何把字符数量限制在 40 以内，以及负增长应该输出怎样的文字。

建议先独立测试“输入 40、25、0、-5、10000”五种情况，再从留白位置调用。不要让条形图替换精确的数值列。这个设计可以练习函数参数、循环和边界处理。
